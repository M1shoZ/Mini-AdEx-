
# Mini Ad-Ex (роутер аукционных запросов)

Сервис маршрутизации аукционных запросов (претаргетинг и параллельный Fan-Out опрос DSP-партнеров) на чистой стандартной библиотеке Go (`net/http`).

---

## Архитектурные особенности решения
- **Ноль внешних фреймворков:** Использована только стандартная библиотека (`net/http`), включая новые возможности маршрутизации методов из **Go 1.22+**.
- **Чистая архитектура (Clean Architecture):**
  - Домен (`internal/domain`) не содержит JSON-тегов и не зависит от транспорта.
  - Транспортный слой (`internal/transport/http`) изолирован через DTO с валидацией входящих данных.
  - Бизнес-логика (`internal/service`) не знает деталей HTTP-сервера.
- **Потокобезопасность без блокировок:** Параллельный опрос партнеров реализован без Data Race через `sync/atomic.Int64` и `sync.WaitGroup`.
- **Защита от зависаний (Graceful Degradation):** Сетевой опрос ограничен общим таймаутом через `context.WithTimeout` (200 мс). Если отдельный партнер зависает или падает, весь аукцион не страдает.
- **Встроенные мок-серверы:** В `cmd/main.go` в фоне поднимаются легковесные моки DSP (быстрые на 9001/9002 и медленный на 9003 для наглядной демонстрации работы таймаута).
- **Graceful Shutdown:** Корректное завершение работы сервера по сигналам `SIGINT`/`SIGTERM` без обрыва текущих запросов.

## 1. Как запустить

### Вариант А: Локально через Go
```
go run cmd/main.go
```
Поддерживаются флаги конфигурации
```
go run cmd/main.go -port 8080 -dsp-timeout 200ms
```
### Вариант Б: В Docker
```
docker build -t mini-adex .
docker run -p 8080:8080 mini-adex
```
### Запуск тестов (с проверком на гонку данных)
```
go test -race -v ./...
```


## 2. Примеры curl-запросов
### Пример 1: Успешный отбор и демонстрация таймаута
```
curl -X POST http://localhost:8080/auction \
  -H "Content-Type: application/json" \
  -d '{
    "request_id": "test-req-1",
    "country": "RU",
    "device_type": "mobile",
    "bid_floor": 1.5,
    "categories": ["news", "sport"]
  }'
```

**Ответ (200 OK):**

```
{
  "request_id": "test-req-1",
  "matched_dsps": [
    "DSP First",
    "DSP Third"
  ],
  "sent": 2,
  "succeeded": 1,
  "duration_ms": 201
}
```

### Пример 2: Фильтрация по заблокированной категории

Отправляем запрос с заблокированной  категорией gambling:
```
curl -X POST http://localhost:8080/auction \
  -H "Content-Type: application/json" \
  -d '{
    "request_id": "test-req-2",
    "country": "RU",
    "device_type": "mobile",
    "bid_floor": 1.5,
    "categories": ["gambling"]
  }'
```

**Ответ (200 OK):**

```
{
  "request_id": "test-req-2",
  "matched_dsps": [
    "DSP Third"
  ],
  "sent": 1,
  "succeeded": 0,
  "duration_ms": 200
}
```

### Пример 3: Ни один партнер не подошел
Отправляем запрос с ценой 0.05 (ниже минимального порога всех партнеров):
```
curl -X POST http://localhost:8080/auction \
  -H "Content-Type: application/json" \
  -d '{
    "request_id": "test-req-3",
    "country": "JP",
    "device_type": "tv",
    "bid_floor": 0.05,
    "categories": ["news"]
  }'
```

**Ответ (200 OK):**
```
{
  "request_id": "test-req-3",
  "matched_dsps": [],
  "sent": 0,
  "succeeded": 0,
  "duration_ms": 0
}
```

## 3. Где лежат партнёры и как добавить нового
Хранилище партнеров изолировано от бизнес-логики через контракт DSPRepo (интерфейс в пакете internal/service).

Текущая реализация находится в файле **internal/repository/dsp_memory.go**.

Чтобы добавить нового партнера, достаточно добавить новый элемент в слайс структуры MemoryDSPRepo:

```
{
    ID:                "55555555-5555-5555-5555-555555555555",
    Name:              "DSP New",
    Endpoint:          "http://127.0.0.1:9005/bid",
    IsEnabled:         true,
    Countries:         []string{"RU", "BY"},     // nil или пустой слайс = любые страны
    DeviceTypes:       []string{"mobile"},       // nil или пустой слайс = любые устройства
    MinBidFloor:       0.8,
    BlockedCategories: []string{"crypto"},
}
```
